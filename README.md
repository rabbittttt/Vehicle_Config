# 车型配置管理

持久目录统一为同级工作区的 `工作台数据/database/vehicle-config/`；独立运行与门户运行读取同一位置。可用 `PLANHUB_DATA_ROOT` 指定数据根（相对路径按应用根解析），应用原有显式数据目录参数继续优先。程序发布不携带业务数据库；发布版使用 `planhub-runtime/database/vehicle-config/`。共享 Excel 仍在原共享目录，数据库集中不改变业务口径。首次升级必须停服迁移，旧目录改名为 `.pre-central-*` 恢复备份，不再参与运行。

第一版独立维护车型、发布阶段、版本与配置适用关系、名称映射、汇总规则及变更历史。前端无外网依赖。不会自动生成 SKU，也不会更改订单、预测或 SOP 的历史资料。

## 启动与停止

开发环境双击 `启动车型配置.cmd`，或在项目根运行 `./start.ps1`。启动器向上查找 Project/.venv，不回退到系统 Python。依赖见 requirements.txt（openpyxl）。前台 Ctrl+C 正常停止；门户接入后由工作台管理进程。独立入口默认 http://127.0.0.1:8790/vehicle-config/，端口可覆盖。

```powershell
./start.ps1 --port 8790 --public-prefix /vehicle-config/
../.venv/Scripts/python.exe -B -m unittest discover -s tests -v
../.venv/Scripts/python.exe -B scripts/build_release.py --version 0.2.0 --destination artifacts/releases/vehicle-config-0.2.0
```

## 前台维护

### 订单配置规则

从顶部「订单配置规则」进入独立编辑区，维护 `GEN_DISPLAY_NAME_MAP`、`MERGE_GROUPS`、`BATTERY_RULES`、`MERGE_OPTIONS`、`OPTION_CONFIG` 五类原脚本配置。版本、动力和 SKU 作为电池规则条件；不新增未约定的版本/SKU 映射常量。初次载入读取实际脚本，缺失常量为空，不填充样例。电池列表支持上移/下移，保留规则优先级；选配金保留金额、默认选配和版本包含/版本精确/座位限制。

开发环境默认目标为 `Project/订单分析/scripts/config/shared_config.py`。可通过服务参数 `--shared-config` 或环境变量 `VEHICLE_CONFIG_SHARED_CONFIG` 指定；正式部署须配置目标脚本的实际路径，并授予服务账号该文件与父目录的写入权限。浏览器不能自选服务器路径。规则入口沿用工作台代理、身份、来源、CSRF 和只读限制。

保存草稿只写共享数据目录中的 `rules/rules.sqlite3`。点击「发布并更新脚本」会显示目标文件、规则差异和 Python 差异，确认后备份至 `rules/backups/`，再原子替换目标文件。脚本之外的源码不修改；不执行或导入源脚本。重复定义、非字面量配置、未知选配限制会阻止写回。编辑修订号和源文件 SHA-256 均参与冲突校验，外部修改后须显式「从脚本重新载入」。发布日志支持意外中断后的恢复；有未决冲突时拒绝继续发布。备份、数据库和真实规则不进入 Git。

五类规则各有 Excel 工作表；支持模板下载、多文件预览、批量粘贴名称映射、复制、删除确认及撤销。列表条件使用单元格内换行；`[]` 可显式清空列表，空白单元格和缺行保留原值。导入电池优先级时须为受影响的规则填写不同序号。导入预览不保存原文件，应用到编辑区后仍需保存或发布。规则历史可恢复到编辑区，再确认发布。

当前订单报表读取已生成的 Excel，现有代码没有消费上述规则的调用点；更新脚本不会重新计算业务 Excel 或刷新历史报表。页面明确保留「业务报表：未重新生成」状态。

车型档案与发布阶段、配置矩阵与版本/配置项目均可直接切换表格视图。筛选支持车型、年款、状态、名称，停用对象可继续维护；列表每页 40 条，勾选“全选筛选结果”涵盖筛选后的全部页。版本和配置项目可一次粘贴最多 200 个名称，每行一项。

矩阵可勾选配置行后批量设置目标版本，默认仅填充“未配置”，预览会显示实际影响数量，不修改跨车型关系。车型、版本和配置项目支持批量改状态。撤销/重做用于当前未保存编辑，保存成功后清空撤销记录；Ctrl+S 保存草稿。请求处理期间锁定控件，修订冲突保留本地编辑供导出。

## 持久数据与发布口径

数据路径优先使用 `--data-dir`；否则使用 `PLANHUB_DATA_ROOT/database/vehicle-config`，未设置根目录时为同级 `工作台数据/database/vehicle-config`。发布包统一传入 `planhub-runtime/database/vehicle-config`；旧版共享目录中的数据须先停服迁移。相对 `--data-dir` 仍按进程目录解析；相对 `PLANHUB_DATA_ROOT` 按项目根解析。

`catalog.sqlite3` 为事务主存储，包含草稿、已发布配置和操作记录；`current.json` 是已发布快照（revision 与 data），`drafts/current.json` 是草稿快照，`history/*.json` 是历史记录。快照以原子替换方式导出；若文件写入失败，接口报错，数据库已提交状态在重启时重新导出。消费者仅读取 current.json，不扫描草稿。备份应在服务停止后备份整个目录；不能只备份 current.json。持久目录不可放在发布包内。OS 生命周期锁阻止新旧进程同时打开同一目录，服务停止后操作系统自动释放锁。

保存使用全目录草稿修订号进行乐观并发检测；冲突返回 409，编辑内容保留在浏览器，可导出后重新载入。发布校验必填、重复名称、关联、日期及汇总成员重复归属；空矩阵为未配置。汇总组仅引用车型，不允许组嵌套，从结构上排除循环。恢复旧记录只进入草稿，新记录仍保留，车型/版本/配置项标为停用，再预览并发布。记录不可删除，改名保留编号。

Excel 模板和导出使用中文工作表与表头：车型档案、发布阶段、版本、配置项目、配置适用关系、名称映射、汇总规则。状态、类别和配置适用状态有下拉选项；模板不带演示数据，附带当前车型、版本和配置的只读引用表。旧版英文工作表和字段键仍兼容。

一次可选择最多 10 个 XLSX 合并预览，页面限制文件总大小 5.5MB（Base64 请求在 8MB 内），服务器限制解压后合计 40MB、单表 10000 行、总计 20000 行、汇总成员关系 2000 条。保存草稿后再导入；预览显示对象级新增、更新、未变更数量，以及文件、工作表、行号和字段错误。同一对象在不同文件中出现相互冲突的值时整批阻止应用，不采用最后文件覆盖。导入预览不会保存原 Excel 或写入配置，应用后还须保存草稿或发布。

编号优先匹配；无编号时按唯一业务键匹配，重复导入同一份表不会再新增对象。车型按品牌、车系、代际、二级代际、年款匹配；版本按车型与名称，配置按车型、类别与名称匹配。改名应保留编号。关联列接受编号、导出的“编号 ｜ 显示名称”，或唯一明确的车型/版本/配置名称；重名、未匹配和跨车型关系必须修正。新车型、版本、配置默认“规划”，新适用关系默认“未配置”。空白单元格及缺行不删除或清空已有字段。公式拒绝导入，Excel 日期可直接识别。

Excel 下载到浏览器的下载目录，服务器不归档原 Excel。导出可选择页面当前编辑内容或已发布版本，维护只读模式仍允许模板和导出。共享目录内持续维护的是数据库与 JSON 快照。

## 工作台接入与部署

应用 ID `vehicle-config`，公共前缀 `/vehicle-config/`。工作台剥离前缀代理至独立回环服务；所有浏览器 URL 使用相对路径。健康接口 `/healthz` 轻量只读，返回 ok、app、public_prefix。前后端同版封装为工作台通用 app-release.json + payload 发布包，构建拒绝覆盖已存在目录，文件带 SHA-256；正式运行使用独立 Python 运行时。门户部署模板提供端口、公共来源、共享根和独立服务参数，发布工具只更新本应用。

本机运行记录 `本机:系统用户名`，不假装是浏览器登录者。正式多人部署必须启用 `--require-proxy-identity` 和 `VEHICLE_CONFIG_PROXY_SECRET`（从服务器外置 secret 文件注入），并通过现有 Windows 身份边界配置 IIS 代理：清除客户端传入的 X-Config-User、X-Config-Proxy-Key，再以已验证的 AUTH_USER 和服务端密钥覆盖。缺少密钥或用户的业务请求返回 403；不设业务角色，所有已获部门访问权成员能力相同。`--read-only` 为全服务维护开关。需由部署人员在目标机配置此可信身份桥，不能仅开启普通反向代理后宣布上线；模板使用 proxyMode=existing 防止普通代理覆盖身份规则。健康接口无需身份，不能代替身份验收。

发布前在目标机验证部门外访问拒绝、代理伪造身份拒绝、真实用户记录、保存后重启、导入导出及前缀资源。不得自动应用 IIS 安全配置。工作台开发代理保留 Host 和 Origin，服务校验二者一致；正式公共来源通过 --public-origin 显式配置。

业务报表当前尚未适配此目录，发布配置不等于业务报表更新。未来消费方须记录 revision，将车型资料和汇总批次一起固化。
