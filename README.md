# 车型配置管理

持久目录统一为同级工作区的 `工作台数据/database/vehicle-config/`；独立运行与门户运行读取同一位置。可用 `PLANHUB_DATA_ROOT` 指定数据根（相对路径按应用根解析），应用原有显式数据目录参数继续优先。程序发布不携带业务数据库；发布版使用 `planhub-runtime/database/vehicle-config/`。共享 Excel 仍在原共享目录，数据库集中不改变业务口径。首次升级必须停服迁移，旧目录改名为 `.pre-central-*` 恢复备份，不再参与运行。

首页按车型阶段列出草稿中的车型资料和发布日程。车型配置维护《小订及首销数据整理》车型汇总 A–N 列及订单脚本的五类规则，日常填数在同一网页的「小订首销填报」办理。前端无外网依赖。

## 启动与停止

开发环境双击 `启动车型配置.cmd`，或在项目根运行 `./start.ps1`。启动器向上查找 Project/.venv，不回退到系统 Python。依赖见 requirements.txt（openpyxl）。前台 Ctrl+C 正常停止；门户接入后由工作台管理进程。独立入口默认 http://127.0.0.1:8790/vehicle-config/，端口可覆盖。

```powershell
./start.ps1 --port 8790 --public-prefix /vehicle-config/
../.venv/Scripts/python.exe -B -m unittest discover -s tests -v
./start.ps1 --show-paths
$releaseVersion = Read-Host '输入新发布版本'
../.venv/Scripts/python.exe -B scripts/build_release.py --version $releaseVersion --destination "artifacts/releases/vehicle-config-$releaseVersion"
```

## 运行诊断与验收

在任意模块打开顶部「数据工具 → 运行路径」，可查当前服务使用的目录、规则脚本和路径来源。离线运行 `./start.ps1 --show-paths` 可查看按本次启动参数计算的路径，无须启动服务。使用发布包运行时，页面还会展示包版本和构建时的 Git 提交（旧包可能缺失）。

| 资产 | 开发默认位置 | 工作台部署默认位置 |
| --- | --- | --- |
| 业务数据根目录 | `Project/工作台数据/database/vehicle-config/` | 运行目录下的 `database/vehicle-config/` |
| 订单规则脚本 | `Project/订单分析/scripts/config/shared_config.py` | `sopSharedConfig` 配置的相对路径，模板值为 `config/shared_config.py` |
| 网页导入、导出 Excel | 从浏览器选取文件，导出到浏览器下载目录 | 同开发版 |

快速验收使用共享 Python 运行 `-B scripts/verify.py`，覆盖单测和已导入数据的车型、日程、填报及导出流程。每次 push 和 PR 也在 Windows CI 上运行快速验收。完整本地验收加 `--full`，需要 Edge、Playwright、Node 和同级计划工作台。首次先核对本机界面并运行 `-B tests/browser_header_check.py --approve` 建立两种宽度的标题栏截图基线；截图放在忽略的 artifacts 目录，后续运行只比较。完整验收还会在填报和筛选过程中测量帧间隔，结果在 artifacts/motion/timings.json。更新系统字体或 Edge 后应人工复核差异。验收发布包加 `--release <发布目录>`，测试使用临时数据库。发布清单中 sourceRevision 是载荷指纹，从 Git 工作区构建时 gitCommit 和 sourceDirty 标记提交及源码是否含本地修改。

## 前台维护

### 车型与日程、小订首销填报

| 入口 | 维护内容 |
| --- | --- |
| 车型与日程 | 同一行查看和编辑代际名、二级代际名、产品档位、能源类型（A–D），以及发布类型、留资日期、小订与首销的发布时段、起止日期和天数（E–N）。小订发布日期与小订开始日期共用一个日期 |
| 小订首销填报 | 「小订进度」「小订期退订进度」「小转大进度」「直接大定进度」「首销期退订进度」各有独立子标签。每个车型一行，可切换发布阶段。「小订进度」支持日序与自然日期，D1 对应所选阶段的小订开始日期 |
| 小订首销填报 → 阶段汇总 | 默认打开此标签。每个车型一行，按所选阶段查看或填报七项经营数量，可展开查看六个比例及其分子、分母 |
| 代际规则 | 代际显示名称、代际合并 |
| 电池与选配 | 电池包规则（含版本和 SKU 匹配条件）、选配名称合并、选配金 |
| 变更记录 | 车型日程与填报的发布记录、脚本规则的变更与恢复 |

车型与日程和小订首销填报共享草稿及发布批次。在「数据工具」左侧点「模板」可下载当前模块的空白 Excel。「车型与日程」模板包含资料和日程的 A–N 列。「小订首销填报」模板包含逐日小订、四张日序进度表和阶段汇总，逐日小订的日期表头可替换或向右追加。

「导入」支持已填写的模板或对应模块导出的 Excel。「车型与日程」按代际名和二级代际名新增或更新资料、日程。「小订首销填报」按阶段匹配核对数量，按阶段和日期或日序匹配明细。空白单元格跳过，数值 0 会导入。确认预览后可撤销，保存草稿或发布后写入数据库。

日程导入按列名匹配可写字段，自动计算的天数取自起止日期；已有手填天数的阶段可导入该项历史值。填报导入只核对有数量的行，可以仅填 D2 等单个日序。附带的日程资料、重复的辅助合计和无关字段会跳过。

多人同时编辑车型与日程或小订首销填报时，各自保留打开页面时看到的内容。保存草稿会合并不同字段、不同日期或不同日序的修改。同一项被改成不同值时，保存窗口列出双方的值，可逐项选择。如果车型或阶段改名后已无法唯一定位，可以放弃该处修改并保存其余内容，也可以取消保存，保留本次编辑。重新打开页面会读取最新草稿。

需要整份迁移时，使用「数据工具 → 导入小订首销旧表」选择《小订及首销数据整理.xlsx》，预览各表的变化后确认替换当前车型日程与填报草稿。可以撤回最近一次整表迁移，报表在重新发布后读取新数据。服务可从空库开始。

整表迁移的预览和确认导入都只读取、校验六张工作表：「车型汇总」「小订by天」「小订期退订进度」「小转大进度」「直接大定进度」「首销期退订进度」。旧表中的「小订进度」「大定进度」（含旧名「总大定进度」）和其他工作表均跳过。

四张进度表只取第一个数量分区，按车型、阶段和日期对应逐日数量。整表迁移也保留数量行里的原始合计和独立起止日期。数量区里的百分比列和后续比例分区都跳过，其中的错误公式不影响预览或导入。完整导出的逐日比例由系统按数量计算，缺少计算所需数据时留空。

逐日小订取自「小订by天」。发布和完整导出中的「大定进度」按车型、阶段和自然日计算。有小订的阶段，将当天的小转大数量与直接大定量相加，缺一项则留空，0 计为已填报。明确无小订且没有独立小转大数量的阶段，直接大定量就是当日大定量。

小订开始或结束日期填 `NA`，表示该车型的这个阶段没有小订。旧表也可使用 `N/A` 或 Excel 的 `#N/A`。另一端可以同样标记或留空，若填了实际日期，预览会提示核对该行。两个日期都留空表示日程待定。无小订的阶段保留首销日程，小订天数留空，网页导出时两个小订日期均写回 `NA`。

车型汇总按字段名匹配，兼容调换列顺序、常见旧名称，以及表头内的空格和换行。Excel 未保存公式结果时，系统可根据同一行的源数据计算已识别的天数、待转单量和比例。旧表使用独立口径的同一行两格相除时，导入保留原公式对应的历史结果，除零的比例留空。其他无法确认结果的公式、未知表头或缺少必需工作表时，预览会提示核对。

「小订by天」按日期表头识别分区，预览按车型明细行计数。整表迁移和填报导入都只从日期列取逐日数量，跳过旧表的「合计」「总计」和备注。导出的明细包含车型、发布阶段和所选日期的数量。完整导出保留原有页脚中按日期汇总的数据。

同一车型有多个发布阶段时，在车型所在行选择阶段。各天排在同一张表里，拖动表格底部的滚动条或在手机上横滑即可查看，左侧车型列保持固定。单击数量或空格可直接录入该天的数据，用「填报」可指定其他日期或日序。「小订进度」标签读取「小订by天」工作表。

「阶段汇总」按车型和发布阶段汇总。逐日数量填齐后，「总小订」取每日小订合计，「小订转大定量」「直接大定量」「大定量」分别取对应首销窗口的逐日数量合计。实际为零的日期填 0，缺日或日期范围不符时保留已有汇总，未上报的留空。两张退订表的退订总数能够互相核实时，「小订后退定」只计一次。首销期净大定和首销期锁单使用独立上报的实绩。六项比例随相关数量计算，旧表独立上报的比例标为历史值。

自动合计随明细更新。网页里手动核定的总数优先，清空该项可恢复自动合计。旧 Excel 没有记录总数的来源。导入时，原汇总与完整明细合计相等的数值后续随明细更新，有差异的原汇总保留。

已有草稿打开时即可看到回填结果。发布后，下游才能读到本次回填。历史发布版本保留当时的数值。

「车型与日程」导出车型汇总的 A–N 列。需要完整旧表格式时，在「小订首销填报」导出，可选草稿或发布版本、工作表、车型及逐日小订的日期范围。车型汇总仍包含「小订待转单」和「小订待转单占比」，进度表仍包含原有比例分区。生成的 Excel 通过浏览器下载。服务不在共享目录生成或维护工作簿。

业务数据保存在数据目录的 `campaigns/campaigns.sqlite3`。发布时将该版数据写入同库的 `publications` 表，同时生成 `campaigns/published.json` 供文件方式接入。订单分析和销量预测默认从数据库读取当前已发布版本，各报表批次固定使用同一修订号；首次发布前会提示先在车型配置发布。经工作台身份验证也可读取 `GET api/campaign/published`，查询历史版本时附上 `?revision=版本号`。Excel 迁入后先核对历史阶段、实际零值、每日数量以及各进度区段，再切换下游数据源。

### 订单配置规则

「代际规则」管理 `GEN_DISPLAY_NAME_MAP` 和 `MERGE_GROUPS`。「电池与选配」管理 `BATTERY_RULES`、`MERGE_OPTIONS` 和 `OPTION_CONFIG`。右上角的车型和年款可组合筛选，切换栏目时保留选择，对车型日程、填报和有车型归属的规则生效。年款按代际名或二级代际名中的“YYYY款”识别。选配名称合并和变更记录为全局数据。搜索词按栏目保留。手机点「筛选」展开车型、年款和搜索框。

切换栏目保留未保存的车型配置和脚本规则。保存草稿、导入导出、撤销和发布作用于当前视图所属的数据。电池规则保留优先级，使用代际、动力及版本、SKU 关键词匹配电池容量。选配金保留金额、默认选配和版本包含、版本精确、座位限制。

在任意模块打开顶部「数据工具 → 从脚本重新载入」，可核对服务当前使用的 `shared_config.py`。确认后，五类规则的草稿与已发布版本都更新为脚本内容，当前车型配置编辑和筛选会保留。数据一致时直接提示结果。规则页底部的「重新载入草稿」用于读取已保存在数据库里的规则草稿。

开发环境默认目标为 `Project/订单分析/scripts/config/shared_config.py`。可通过服务参数 `--shared-config` 或环境变量 `VEHICLE_CONFIG_SHARED_CONFIG` 指定；正式部署须配置目标脚本的实际路径，并授予服务账号该文件与父目录的写入权限。浏览器不能自选服务器路径。规则入口沿用工作台代理、身份、来源、CSRF 和只读限制。

规则草稿保存在当前数据目录下的 `rules/rules.sqlite3`。点击页底「发布」时，待发布的脚本规则会列出目标文件、规则差异和 Python 差异，确认后备份至 `rules/backups/`，再原子替换目标文件。脚本之外的源码不修改；不执行或导入源脚本。重复定义、非字面量配置、未知选配限制会阻止写回。编辑修订号和源文件 SHA-256 均参与冲突校验，外部修改后须显式「从脚本重新载入」。发布日志支持意外中断后的恢复；有未决冲突时拒绝继续发布。预览和发布都会按 SOP 的归并口径检查 `MERGE_GROUPS`：全角字符、独立的 BETA 标记与空白归一后，组名须唯一、每个成员只能出现一次，组不能再作为成员。旧规则可先载入，在草稿中修正后再发布。源文件原有的编码声明和成员拼写会保留。备份、数据库和真实规则不进入 Git。

五类规则各有 Excel 工作表；支持模板下载、多文件预览、批量粘贴名称映射、复制、删除确认及撤销。列表条件使用单元格内换行；`[]` 可显式清空列表，空白单元格和缺行保留原值。导入电池优先级时须为受影响的规则填写不同序号。导入预览不保存原文件，应用到编辑区后仍需保存或发布。规则历史可恢复到编辑区，再确认发布。

选配金支持固定金额和按条件定价。网页可逐条维护匹配条件及金额，也可单独添加默认价。Excel 的「金额」列接受数字或 JSON 对象，例如 `{"条件甲":3000,"default":1000}`。缺少默认价的规则会保留原有条件，写回脚本时也保留条件顺序。

SOP 从发布的共享脚本读取 `MERGE_GROUPS`。订单报表展示的数据来自已生成的 Excel；发布脚本规则后，已有 Excel 和历史报表仍是原结果，需要通过对应的生成流程更新。

## 持久数据与发布口径

数据路径优先使用 `--data-dir`；否则使用 `PLANHUB_DATA_ROOT/database/vehicle-config`，未设置根目录时为同级 `工作台数据/database/vehicle-config`。发布包统一传入 `planhub-runtime/database/vehicle-config`；旧版共享目录中的数据须先停服迁移。相对 `--data-dir` 仍按进程目录解析；相对 `PLANHUB_DATA_ROOT` 按项目根解析。

数据根目录按业务划分，服务进程共用的 `service.lock` 位于根目录。

| 子目录 | SQLite 主库 | 同目录下的相关文件 |
| --- | --- | --- |
| `catalog/` 旧版独立车型档案与配置矩阵 | `catalog.sqlite3` | 已发布快照 `current.json`、草稿 `drafts/current.json`、历史 `history/<事件号>.json` |
| `campaigns/` 车型与日程、小订首销填报 | `campaigns.sqlite3` | 发布后生成 `published.json` |
| `rules/` 代际、电池与选配规则 | `rules.sqlite3` | 发布脚本时备份至 `backups/` |

旧服务停止后，用新版启动时会自动把数据根目录原有的车型档案库及其快照迁入 `catalog/`。迁移保留草稿、发布修订号和操作历史，中断后可再次启动续迁。新旧位置若已有两份车型库，服务会停止启动，保留两份文件供核对。直接读取旧版车型快照的程序应将路径更新为 `catalog/current.json`。网页和原有 API 继续使用原地址。备份时请停服并备份整个数据根目录。

## 工作台接入与部署

启用代理密钥后，每个业务请求都需要可信代理身份。`--require-proxy-identity` 还会在启动阶段检查密钥，缺失时终止启动。健康检查可使用回环地址或 `--public-origin` 中配置的主机。

车型配置与脚本规则的变更记录每页 40 条，搜索覆盖全部历史。若脚本发布中断且源文件已被外部修改，重新载入前须确认。该次待发布内容会保存在「变更记录 → 脚本变更记录」中，可恢复到编辑区。

应用 ID `vehicle-config`，公共前缀 `/vehicle-config/`。工作台剥离前缀代理至独立回环服务；所有浏览器 URL 使用相对路径。健康接口 `/healthz` 轻量只读，返回 ok、app、public_prefix。前后端同版封装为工作台通用 app-release.json + payload 发布包，构建拒绝覆盖已存在目录，文件带 SHA-256；正式运行使用独立 Python 运行时。门户部署模板提供端口、公共来源、共享根和独立服务参数，发布工具只更新本应用。

车型配置与 SOP 使用相同的操作人来源。工作台通过 `postMessage` 向车型配置页面传入外层系统的 `account`、`roleCode` 和 `roleName`。页面将三项随业务请求放入 `Sop-Frame-Identity`，服务使用其中的 `account` 记录操作人。工作台本机预览使用 `local-debug`。独立打开车型配置时，维护人自行填写署名，浏览器会记住上次填写的值。独立调用写入接口时，通过 JSON 顶层字段 `owner` 提交署名。

工作台 Docker 版由公司认证网关校验访问资格。启动器从包外 `planhub-runtime/config.json` 的 `vehicleSecret` 注入 `VEHICLE_CONFIG_PROXY_SECRET`，并传入 `--require-proxy-identity`。配置服务校验 `X-Config-Proxy-Key`，在代理模式下拒绝缺少门户账号的业务读写。`--read-only` 控制整个服务的写入。

部署验收应覆盖未获部门访问资格的请求、伪造身份、操作人记录、保存后重启和 Excel 导入导出。公共地址须与 `--public-origin` 一致，健康接口 `/healthz` 单独用于检查服务可用性。

所有栏目共用页底的「发布」。页底「配置草稿」显示全页的修改和待发布状态，切换栏目时保持一致。确认窗口汇总车型日程与小订首销数据，以及代际、电池与选配规则的待发布变更，包括已应用的页面编辑和已保存的草稿。确认一次后，系统依次发布有变更的数据与规则。若中途失败，结果窗口列出已完成的组，点「重新核对」可继续处理剩余变更。接入车型快照的报表应记录 `revision` 和汇总批次，以便复核历史结果。
